# PDR-0010: Bank loomweave 1.4.1 public-surface tags locally

- **Date:** 2026-07-10
- **Status:** accepted — inward-facing checkpoint. Public push / tag / package
  publish remains a separate owner-gated action.
- **PRD:** none (tactical product-surface correctness patch for Plainweave's
  denominator; implementation plan:
  `docs/plans/2026-07-10-public-surface-tags-for-plainweave.md`)
- **Tracker:** no dedicated release issue. Related live context: Plainweave was
  missing Loomweave-side public-surface functionality; Filigree still shows
  ADR-054 Rust reachability roots (`clarion-05fdd0490e`) as a stale concurrent
  claim, not this owner-session's work.

## Context

Plainweave's coverage denominator depends on Loomweave surfacing public product
doors honestly: exported APIs, CLI commands, HTTP routes, and entry points. The
prior Plainweave behavior degraded honestly, but the underlying defect was
Loomweave not emitting enough tags and MCP shortcuts for those surfaces.

The first review pass found two correctness gaps in the proposed fix: the
standalone Rust plugin distribution lockfile still carried the vulnerable
`crossbeam-epoch` version, and Python CLI tagging missed common main-guard
wrappers. A final review pass found the new Warpline conformance oracle was
non-hermetic because it auto-ran against `/home/john/warpline` whenever that
sibling checkout happened to exist.

## Options

1. **Leave the work as a plan / review artifact.** Rejected: Plainweave still
   lacks the Loomweave-side functionality it needs; this keeps the denominator
   incomplete.
2. **Bank a local 1.4.1 patch and install it into the local uv toolchain.**
   Chosen: it closes the missing Loomweave functionality, preserves review fixes,
   and gives local operators a verified build without crossing the public-release
   boundary.
3. **Publish 1.4.1 to public channels now.** Not chosen in this checkpoint:
   public package publication and tag pushes are outward-facing one-way doors.
   They require explicit owner authorization, as in PDR-0009.

## The call

**Option 2 — bank the local 1.4.1 checkpoint.** `main` now contains:

- MCP shortcut surfaces for `entry-point`, `http-route`, `exported-api`, and
  `cli-command`, with exact docstring/tool-list budget coverage.
- Python extractor support for explicit and augmented `__all__`, re-exported
  modules, manual CLI patterns, `SystemExit` / `sys.exit` / bare `exit` / `quit`,
  and runner wrappers (`asyncio.run`, `anyio.run`, `typer.run`).
- Root and standalone Rust-plugin distribution lockfiles resolving
  `crossbeam-epoch` to `0.9.20`.
- A Warpline churn conformance oracle that is hermetic by default: `WARPLINE_REPO`
  must be set to opt into sibling checks, while `LOOMWEAVE_DRIFT_REQUIRED=1`
  still turns an unconfigured sibling into a hard failure.
- Local uv tools reinstalled at `1.4.1` for `loomweave`,
  `loomweave-plugin-python`, and `loomweave-plugin-rust`.

This did **not** push `main`, tag `v1.4.1`, publish PyPI wheels, create a GitHub
Release, or publish crates. Those remain external release actions.

## Reversal trigger

Reopen if Plainweave still reports a missing public-surface denominator class
that maps to Loomweave's owned extraction/tag/MCP surface, or if the local
`1.4.1` build fails to install/launch with both language plugins from uv.

If the owner asks to externalize the patch, run the release gate as a new
outward-facing action: verify the package set, push only after explicit
authorization, and publish the current `1.4.1` package set only while those
artifacts are still unpublished. If any public `1.4.1` artifact already exists,
ship the remedy as a later patch instead of mutating published artifacts in
place.
