# Loomweave 1.4.2 Local Release Design

## Goal

Cut a lockstep local patch release for the work currently on `main`, document
the release accurately, and replace the installed uv tool stack with wheels
built from the committed 1.4.2 checkout.

## Version scope

- Bump the Cargo workspace, internal dependency requirements, Python plugin,
  CLI wheel, Rust-plugin distribution, plugin manifests, lockfiles, and pinned
  version assertions from 1.4.1 to 1.4.2.
- Preserve ontology and wire-contract versions; these fixes do not change the
  entity/tag vocabulary or federation API schema.
- Use the repository's lockstep checker as the authoritative completeness gate.

## Changelog scope

- Promote the current `Unreleased` fixes into a `1.4.2` section dated
  2026-07-12, leaving a new empty `Unreleased` heading above it.
- Correct the duplicate-locator compatibility note: the deprecated
  `first_source_file_path` alias preserves the first declaration path.
- Add explicit entries for overload-stub export classification and Unix project
  basenames containing `:`.

## Verification and installation

1. Regenerate the Rust and Python lockfiles through their package managers.
2. Run the version-lockstep checks and the tests affected by version assertions.
3. Run formatting, lint, full Rust/Python tests, and the Wardline ERROR gate.
4. Commit the release metadata on `main`.
5. Build local CLI, Python-plugin, and Rust-plugin wheels from that commit.
6. Force-reinstall all three uv tools with cache bypass, then verify version
   1.4.2, executable provenance, byte-identical manifests, and `loomweave
   doctor`.

## Non-goals

- No Git tag, remote push, GitHub release, or registry publication.
- No changes to unrelated worktrees or running MCP processes.
